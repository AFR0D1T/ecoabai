# EcoAbai

Экологическая платформа для села Абай (Казахстан): карта проблем и мероприятий, обращения жителей, субботники, баллы и значки, админ-панель для администрации.

Фронтенд — React + Vite (`/`), бэкенд — Python FastAPI (`backend/`). Данные — SQLite в разработке, Postgres в продакшене.

## Стек

React 18 + TypeScript (strict) + Vite · Tailwind CSS + компоненты в стиле shadcn/ui (Radix) · React Router v6 · Leaflet + react-leaflet + react-leaflet-cluster (схема — OpenStreetMap, спутник — Esri; без ключей) · TanStack Query · react-hook-form + zod · Recharts · react-i18next (ru / kk) · date-fns · lucide-react · sonner (тосты).

Бэкенд: FastAPI · SQLAlchemy 2 · Pydantic 2 · Argon2 · PyJWT · Pillow · pytest.

## Запуск

Нужны Node.js 18+ и Python 3.11+.

**Бэкенд** (http://127.0.0.1:8000, документация API — http://127.0.0.1:8000/api/docs):

```bash
cd backend
python -m venv .venv
.venv\Scriptsctivate
pip install -r requirements.txt
python run.py
```

При первом запуске создаётся `backend/ecoabai.db` с демо-данными. Пересоздать базу с нуля: `python -m app.seed --reset`. Тесты: `python -m pytest`.

**Фронтенд** (http://localhost:5173, запросы `/api` проксируются на бэкенд):

```bash
npm install
npm run dev
npm run build
```

## Где менять центр карты

`src/config.ts` → `DEFAULT_MAP_CENTER` / `DEFAULT_MAP_ZOOM` (помечено `// TODO: уточнить координаты села Абай`).
Эти значения — только стартовые: админ может сохранить свой вид карты в **Админка → Настройки → «Сохранить текущий вид»** (хранится в `VillageSettings`).

## Как устроен слой данных

```
Компонент → хук из src/hooks (TanStack Query) → src/api/* → src/api/http.ts → FastAPI (backend/app/routers/*)
```

* Компоненты не обращаются к сети напрямую — только через хуки из `src/hooks/`.
* `src/api/http.ts` — единственный HTTP-клиент: `credentials: 'include'`, заголовок `X-CSRF-Token`, автоматическое обновление сессии при `token_expired`.
* Ошибки приходят как `{"code": "..."}` и переводятся через `t('errors.<code>')`.
* Фото сжимаются на клиенте до 1600 px и загружаются в `POST /api/uploads`. Сервер проверяет, что это картинка, перекодирует её в JPEG (EXIF и GPS удаляются) и возвращает `/api/uploads/<id>.jpg`.
* Баллы, значки, уведомления и статистика считаются на сервере (`backend/app/services`).

## Безопасность

* **Токены не видны JavaScript.** Access-токен (JWT, 15 мин) и refresh-токен (30 дней) лежат только в `httpOnly` cookie. В `localStorage` и в теле ответов их нет. Refresh-cookie имеет `path=/api/auth` и `SameSite=Strict`. В prod (`COOKIE_SECURE=true`) cookie получают префиксы `__Host-` и `__Secure-` и флаг `Secure`, добавляется HSTS.
* **Refresh-токены** в БД хранятся только как SHA-256-хэш и меняются при каждом обновлении. Если кто-то повторно использует старый токен (признак кражи), все сессии пользователя отзываются.
* **CSRF:** изменяющие запросы принимаются только с разрешённых `Origin`, а также требуют заголовок `X-CSRF-Token`, который сверяется с хэшем в access-токене. CSRF-токен хранится только в памяти вкладки.
* **Пароли** хэшируются Argon2id. Время ответа на вход одинаковое, есть такой email или нет. Сброс пароля одноразовый, действует 1 час и завершает все сессии.
* **Права проверяет сервер** на каждом запросе (роль берётся из БД, а не из токена). Блокировка пользователя действует сразу: все его сессии отзываются. Админ не может заблокировать или разжаловать сам себя. Через `PATCH /auth/me` нельзя поменять роль или баллы (лишние поля → 422).
* **Приватность:** в публичных списках скрыто, кто автор обращения; в рейтинге показывается только первая буква фамилии; отклонённые обращения видят только автор и админ.
* **Ограничение частоты** запросов на вход, регистрацию, сброс пароля, загрузку фото и создание обращений.
* **Входные данные** проверяются pydantic-схемами. URL фото принимаются только вида `/api/uploads/...` (никаких внешних ссылок и `javascript:`). Загруженные файлы раздаются с `CSP: sandbox` и `nosniff`.
* Ошибки сервера наружу не раскрываются. Документация `/api/docs` в prod отключена.

`backend/tests/test_security.py` — 18 тестов на всё перечисленное (cookie, CSRF, ротация refresh-токенов, права гостя, жителя и админа, загрузка файлов, начисление баллов).

## Роли и доступ

* **guest** — карта, мероприятия, рейтинг. Попытка записаться/сообщить → модалка «Войдите, чтобы продолжить».
* **resident** — запись на мероприятия, обращения, профиль, уведомления.
* **admin** — всё + `/admin/*`. Сервер проверяет роль в каждом админ-эндпоинте; на фронте guard `RequireAdmin`: житель → редирект на главную с тостом, гость → на вход. Код админки (`pages/admin/*`, Recharts) грузится отдельным чанком через `React.lazy` — житель его не скачивает.

## Геймификация (`backend/app/services/gamification.py`)

* +10 баллов, когда обращение подтверждено (статус `in_progress` или `resolved`). Начисляется один раз; это гарантирует уникальный индекс в БД.
* +`points_reward` (по умолчанию 20), когда админ отметил участие как `attended`. Снятие отметки отменяет начисление.
* 0 баллов за запись и за неподтверждённое обращение.
* Значки: 🌱 Первый шаг, 👁️ Зоркий глаз, 🧹 Субботник ×3, 🌳 Посадил дерево, ♻️ Сортировщик, 🏆 Эко-лидер месяца. При получении создаётся уведомление на языке пользователя, а фронт показывает анимированный тост.

## Деплой

**Фронтенд (Vercel):** в `vercel.json` замените `YOUR-API-HOST` на адрес бэкенда. Vercel будет проксировать `/api/*`, поэтому для браузера всё останется на одном домене и cookie будут работать без CORS.

**Бэкенд:** скопируйте `backend/.env.example` в `.env` и задайте:
* `ECOABAI_ENV=prod`, длинный случайный `ECOABAI_SECRET_KEY`, `ECOABAI_COOKIE_SECURE=true` (без них сервер не запустится);
* `ECOABAI_DATABASE_URL=postgresql+psycopg://...`, `ECOABAI_ALLOWED_ORIGINS=["https://ваш-домен"]`, `ECOABAI_SEED_DEMO=false`.

Запуск: `uvicorn app.main:app --host 0.0.0.0 --port 8000 --proxy-headers`, только за HTTPS. Папку `uploads/` нужно сохранять между деплоями (диск или объектное хранилище).
