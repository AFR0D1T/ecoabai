# Деплой EcoAbai

Приложение состоит из трёх частей: фронтенд (статические файлы), API на FastAPI и база Postgres, плюс папка с фото.
Проще и надёжнее всего держать всё на **одном сервере** через `docker compose`: Caddy сам получает HTTPS-сертификат,
отдаёт фронт и проксирует `/api`. Фронт и API на одном домене, поэтому защищённые cookie работают без CORS.

## Где разместить

Условия бесплатных тарифов меняются, поэтому перед выбором проверьте их на сайте провайдера.

| Вариант | Цена | Подходит? |
|---|---|---|
| **Oracle Cloud Always Free** (ARM VM, до 4 vCPU / 24 ГБ RAM, ~200 ГБ диск) | бесплатно, нужна карта для верификации | ✅ Лучший бесплатный вариант для пилота: полноценный сервер, всё по этой инструкции. Минус: иногда нет свободных мощностей в регионе. |
| **VPS в Казахстане** (ps.kz, hoster.kz и др.) | от ~2–5 тыс. ₸/мес | ✅ Рекомендую для официального запуска: данные жителей хранятся в РК (см. ниже). |
| Hetzner / другой зарубежный VPS | ~4–5 €/мес | ✅ Дёшево и стабильно, но серверы в Европе. |
| Render / Koyeb (бесплатные тарифы) | бесплатно | ⚠️ Только для демо: сервис «засыпает» без запросов (первый заход ждёт 30–60 с), диск временный — **загруженные фото пропадут** после перезапуска. |
| Vercel / Netlify / Cloudflare Pages | бесплатно | Только фронтенд. API и база всё равно нужны отдельно (`vercel.json` уже настроен проксировать `/api`). |
| Neon / Supabase (Postgres) | бесплатно до ~0,5 ГБ | Можно взять как базу, если API хостится на платформе без своей БД. |

**Важно для официального запуска.** Закон РК «О персональных данных и их защите» требует хранить базы с персональными данными
граждан РК на территории Казахстана. В EcoAbai хранятся имена, email и улицы жителей. Если проект запускается от имени акимата,
уточните требования у юриста и выбирайте казахстанский хостинг.

**Домен.** Свой `.kz` домен стоит недорого. Для теста подойдёт бесплатный `sslip.io`: если IP сервера `203.0.113.10`,
используйте домен `203-0-113-10.sslip.io`, и HTTPS выпустится автоматически.

## Установка на сервер (Ubuntu 22.04/24.04, любой VPS)

1. Откройте в файрволе/панели провайдера порты **80** и **443** (в Oracle Cloud — в Security List и в `iptables` на самой машине).
2. Установите Docker:
   ```bash
   curl -fsSL https://get.docker.com | sudo sh
   sudo usermod -aG docker $USER && newgrp docker
   ```
3. Скопируйте проект на сервер (`git clone …` или `scp -r`) и перейдите в папку проекта.
4. Создайте настройки:
   ```bash
   cp deploy/.env.example .env
   nano .env
   ```
   Заполните `DOMAIN`. В `SECRET_KEY` и `POSTGRES_PASSWORD` вставьте результат `openssl rand -base64 48` (разные значения).
   Для показа с демо-данными поставьте `SEED_DEMO=true`, для реального запуска — `false`.
5. Запустите:
   ```bash
   docker compose up -d --build
   docker compose logs -f web api
   ```
   Через минуту сайт откроется на `https://ваш-домен`.

## Первый админ (когда SEED_DEMO=false)

Зарегистрируйтесь на сайте как обычный житель, затем назначьте себе роль админа:

```bash
docker compose exec db psql -U ecoabai -d ecoabai -c "update users set role='admin' where email='you@example.kz';"
```

Дальше в админке: **Настройки** → население, центр карты («Сохранить текущий вид»), список улиц.

## Обслуживание

* Обновление: `git pull && docker compose up -d --build`.
* Резервная копия базы (настройте ежедневно через cron):
  ```bash
  docker compose exec -T db pg_dump -U ecoabai ecoabai | gzip > backup-$(date +%F).sql.gz
  ```
* Фото лежат в томе `uploads`, сертификаты — в `caddy_data`. Удалять эти тома нельзя.
* Ссылки для сброса пароля пока пишутся в лог: `docker compose logs api | grep "reset link"`. Для писем нужно подключить SMTP (TODO в `backend/app/routers/auth.py`).

## Что уже настроено для продакшена

* HTTPS с автопродлением (Caddy + Let's Encrypt), HSTS, строгая CSP (запрещены сторонние скрипты), запрет встраивания во фреймы.
* Cookie `__Host-`/`__Secure-` с флагом `Secure`. Сервер не стартует в prod без `SECRET_KEY` и HTTPS-cookie.
* Документация API (`/api/docs`) в prod отключена. API работает не от root, у контейнера есть healthcheck.
* Сжатие gzip/zstd. Файлы сборки кэшируются на год, `index.html` и `sw.js` не кэшируются (обновления приходят сразу).
